05The questions

Questions, answered

The ten that reach us most often by email and on the issue tracker. Open any one — each is a single paragraph, and none of them is a sales pitch.

What is Blocks MailCraft?

Blocks MailCraft is an open-source drag-and-drop editor for HTML email templates, shipped as a single Web Component — one <mailcraft-editor> tag. You hand it HTML and it hands back send-ready HTML, with no proprietary document format in between. It is MIT licensed and published on npm as @seliseblocks/mailcraft.

Is it really free, or is there a paid tier?

It is free, and there is no paid tier to graduate to. The whole editor is MIT-licensed source: no seats, no per-email metering, no plan-gated features and no “contact sales” — white-label, editor localization, HTML import and conditional logic all arrive in the one install.

Which frameworks does Blocks MailCraft work with?

All of them, because it is a standard custom element rather than a framework component. The same tag runs in React, Angular, Vue and Svelte, and in a plain HTML page loaded with a <script> tag — there is no per-framework wrapper package to keep up with.

Does it need a server, an account or an API key?

No. Blocks MailCraft has zero runtime dependencies and makes no network requests of its own — no vendor cloud, no iframe, no telemetry, no token to refresh. It runs from a file:// page, which is also the short answer to where your templates go: nowhere you did not send them.

Can I import the email templates I already have?

Yes, and it is not metered. Existing HTML imports into an editable block canvas and exports as HTML again; opening a design and saving it without touching anything gives you back what you put in, so migrating off another editor is not a one-way door.

How many languages does the editor interface support?

Thirty-one, with right-to-left layout switched on automatically for Arabic. Beyond translation, all 189 interface labels can be overridden from your own copy deck, so the editor can use your product’s vocabulary rather than ours — and be white-labelled while it does.

How do I choose between this and a hosted editor SDK?

It comes down to what you want to own. A hosted SDK is a service: someone else runs the editor, ships the improvements and carries the support burden, on the terms they publish — worth evaluating directly with the vendor against your own requirements. Blocks MailCraft is the other trade. The entire editor is MIT source running inside your own page, with no vendor service to authenticate against and nothing to call home to. You own it outright, which also means you maintain it.

Are there open-source alternatives?

Yes, several good ones, and which one fits depends on your stack — most are React libraries, or general-purpose page builders adapted to email with a compiler in front. Blocks MailCraft makes a narrower bet: a framework-agnostic Web Component with zero runtime dependencies and email-client-safe export, so it drops into any page without bringing a toolchain along. Compare them against your own requirements rather than ours.

How do I install Blocks MailCraft?

Run npm install @seliseblocks/mailcraft and import the module, or drop the prebuilt bundle into a page with a script tag from unpkg or jsDelivr — no build step either way. The quick start is five minutes end to end; the guide covers framework wiring, storage, AI and i18n contracts.

How does it relate to SELISE Blocks?

Same team, two ways to use it. Blocks MailCraft is standalone and stays that way, and it also ships pre-wired inside SELISE Blocks Cloud, where Email Management, file storage for the image library, identity, secrets and observability share one console per project and environment.
